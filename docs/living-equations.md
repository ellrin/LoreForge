# 會動的方程式（規劃，2026-11-13）

作者的要求：論文裡的方程式（大多是損失函數、深度學習的函數）可以動：每個變數變化對輸出的影響看得到；
能輸出 GIF 放進投影片（一鍵做簡報時自動把關鍵算式動畫化）。更遠的目標：描述「分佈的變化」
（統計分佈、二分類如何靠 loss 逼近、多類別分群，GAN／VAE／diffusion）。

共用功能，不屬於任何一個 app：算式解析與取值、模板、敏感度、動畫與 GIF 放在 commons（`lore-plot` 的一種圖：
`kind: "equation"`，同一個繪圖編輯器、同一份規格、同一套 TeX 字形），LoreReader、PaperComposer、SlideComposer 都用同一套。

## 三層，誠實的可行性

| 層 | 內容 | 自動化 | 怎麼保證正確 |
|---|---|---|---|
| 1 單一算式 | 損失函數與常見函數：CE、BCE、focal（γ, α）、Dice、Huber、MSE、KL（兩個高斯）、InfoNCE（τ、負樣本數）、triplet margin、label smoothing、softmax 溫度、ReLU／GELU／SiLU／sigmoid／tanh | 全自動：模型讀論文的 LaTeX 與 LoreReader 的符號表，選橫軸、參數滑桿與範圍（預設值取論文的） | 常見的用內建模板（正確的寫法），模型只對參數；模板外的由模型寫成算式，伺服器先取值檢查（有限、範圍合理），旁邊並排原 LaTeX，作者確認 |
| 2 分佈的變化 | 二分類：loss 如何推動決策邊界；多類別：softmax 分區、k-means、GMM 的 EM 一步步收斂；統計分佈 | 模型判斷屬於哪個模板、套論文的設定（損失、類別數、margin、溫度） | 小的模擬資料、畫面上真的跑（數百個參數），每一步都是算出來的 |
| 3 生成模型 | diffusion（目標＝高斯混合時反向去噪可用公式精確算，不用訓練；套論文的 noise schedule、步數）、VAE（2D 潛在空間與 β）、GAN（追目標分佈，先算好成功的版本再播） | 模型選模板、套參數，作者確認（同流程圖：討論 → 決定 → 生成） | 示意版：用正確的小例子示範機制 |

做不到：自動重現論文真正的模型在真實資料上的行為（沒有權重與資料）。

## 第一層要做的

1. **圖的規格**（lore-plot `kind: "equation"`）：算式（模板 id ＋參數，或安全的算式語法，不用 eval）、橫軸變數與範圍、
   參數滑桿（範圍、預設、步長）、要畫的曲線（函數值、對某參數或對輸入的導數）、標示（論文的值）。
2. **滑桿互動**：拖滑桿曲線即時變；**敏感度**：目前這一點對每個參數的數值偏微分，畫成「調這個參數，輸出變多少」的長條（正規化），
   可切換顯示梯度曲線（例：focal 的 γ 如何壓低簡單樣本的梯度）。
3. **GIF**：選一個參數自動掃過一段範圍（來回），逐格畫成 GIF（背景、字型照論文或簡報的樣式，不用 app 主題），存檔；`.pptx` 直接播 GIF。
4. **入口**：LoreReader 點方程式 →「動起來」（用 LoreReader 抽出的 LaTeX 與符號表）；PaperComposer／SlideComposer 的繪圖工具新增「方程式」；
   SlideComposer 一鍵做簡報（論文報告）在方法頁自動為主要損失函數放一張 GIF（可在微調視窗關掉）。
5. **模型任務**：`equation-plot`（lore-llm，雲端優先）：LaTeX ＋符號表 ＋上下文 → 規格；結果一律先取值檢查。

## 狀態（2026-11-13）

第一層完成：見 `docs/plot.md` §10。規格 `kind: "equation"`、安全算式語言（Rust＋JS 兩份、共用測試案例）、18 個模板（每個的性質都測）、
`equation-plot` 任務（模板優先；一般路徑＝算式＋化簡假設＋可檢查的性質，伺服器逐條驗證）、編輯器（滑桿、敏感度、∂f/∂x／∂f/∂θ 曲線、曲線族、
互動畫面跟主題：發光、變形、3D 曲面＋滾珠；輸出跟圖的樣式）、變數顏色角色（lore-notation `Entry.color`）、GIF（伺服器編碼、規格在檔案裡）。
入口：LoreReader 動起來、PaperComposer／SlideComposer「會動的方程式」、論文報告自動放主要損失的 GIF（只在模板＋論文說了調哪個參數＋性質全過時）。

沒有在真的環境測過：真的模型、PowerPoint／Keynote 播放 GIF、WKWebView（Tauri）裡 3D 畫布的效能（headless Chrome 量到約 60 fps）。

## 狀態（2026-11-14）：第二層＋放映「互動」

做好的（細節見 `docs/plot.md` §11）：
- **模擬場景**（`eq.sim`，commons）：`fit`（1D 高斯／2D 高斯混合追目標分佈，損失 = Σ wᵢ Lᵢ：正向 KL／交叉熵、反向 KL、樣本 NLL、動差、錨點、負熵、密度 MSE、K 類 softmax 的 one-hot／label smoothing、自訂項＝安全算式）、`cluster`（k-means、GMM-EM、softmax 分區）；沒有 `sim` 的方程式圖就是第一層的曲線。
  數值核心 `ui/plot/simcore.js`（不碰 DOM，node 測試）；Rust `equation::sim` 驗規格、算同樣的項（共用案例 `simtests.json`）、比對 LaTeX 給場景（`suggest`）。7 個場景在 `equations.json` 的 `scenes`。
- **每一項的貢獻**：右邊一項一列（開關、權重、LaTeX、拉力 −wᵢ∂Lᵢ/∂θ、加權值）、堆疊 loss 圖與權重改變的標記；動畫裡每項一支拉力箭頭。顏色：lore-notation 的角色優先，否則主題色。
- **GIF 節奏**：75 % 畫面變化＋25 % 時間，最後停住；所有方程式 GIF（第一層的參數掃描也是：照曲線變化取值、折返點停）。只存變了的部分、熱圖抖色。
- **SlideComposer 放映「互動」**：方程式圖（GIF 裡帶方程式規格）那頁出現「互動」（I）：觀眾畫面變成即時畫面（全畫面、Lore 主題），簡報者畫面是控制台（權重、開關、加項、拖目標、播放／暫停／一步／重來、速度），簡報者跑模擬、把狀態送給觀眾；Esc 或按鈕回到投影片。單一螢幕也能用。第一層的曲線圖：滑桿控制參數。
- **跨 app**：LoreReader 的 ✦ 動起來與 KnowledgeBase 卡片上的展示式子（右邊的 ✦）都走 `LorePlot.animateLatex`：組合損失或分佈的目標先問要哪個模擬（不用模型），其他照第一層。KnowledgeBase 現在掛 `/plot`（沒有模型任務：提案改成手動選）。

沒有在真的環境測過：WKWebView（Tauri）裡模擬的效能（headless Chrome 1920×1080 都是 60 fps）；PowerPoint／Keynote 播放帶逐格延遲與透明局部格的 GIF；真的雙螢幕放映。

### 跨 app 的提案（等作者決定）

1. **PaperComposer**：模擬圖存進論文時是 `plan` 跑完的最後一格（向量＋熱圖點陣）。要不要改成「小倍數」（例如 4 個時間點並排）或乾脆不給論文用、只給投影片？
2. **論文報告自動放模擬**：`sim::suggest` 能認出組合損失；要不要在方法頁自動放模擬 GIF（目前只放第一層的曲線 GIF，條件很嚴）？權重與 plan 從論文的超參數段落來，要模型任務（`equation-plot` 加上 `sim` 輸出），作者要先看幾個例子。
3. **LoreReader 的符號表 → 項的名稱**：論文的 λ₁、β 現在只用來對顏色；可以讓 `animateLatex` 把論文的權重值（消融表）帶進場景的 `w`。要模型讀超參數段落。
4. **KnowledgeBase 卡片內嵌即時畫面**：現在是 ✦ 打開編輯器。也可以在卡片裡直接嵌一個小的即時畫面（卡片存 `sim` 規格，像圖片一樣）。牽涉卡片格式（`nodes/<id>.json` 多一種附件），作者決定。
5. **LoreEcho 語音講解**：放映「互動」時，LoreEcho 可以念出「權重 b 調到 1，q 被拉向右邊的峰」這種一句話（從拉力與 loss 變化自動產生）。要接 LoreEcho 的 TTS 與放映的 BroadcastChannel。
6. **觀眾端互動**：現在觀眾畫面只顯示；要不要讓聽眾掃 QR 在手機上調權重（多人）？牽涉網路與隱私，預設不做。
7. **主題 vs 投影片色盤**：互動畫面照規格用 Lore 主題；若作者希望放映時跟投影片的色盤一致（深色／淺色底版），可以加一個開關。
