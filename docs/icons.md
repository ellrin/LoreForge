# 圖示（流程圖、時間軸、投影片共用）

狀態：2026-11-25。第一階段完成；第二階段做了「圖裡畫得出圖示」，其餘未做（見最後一節）。

## 要做到什麼

論文的流程圖、時間軸和投影片裡，需要一個小圖表示「醫師」「路由器」「資料庫」時，從兩套開源圖示庫挑，畫成向量，匯出到 PowerPoint 還是可以改顏色的形狀。

- 圖示庫：`commons/icons/`（Tabler Icons，MIT；Health Icons，圖示是 CC0），整套放在 repo，授權檔在旁邊。兩套都可以用在發表的論文。
- 在 L-Brain 是流程圖那一組下面的一個類別「圖示」：只列兩個素材包和作者寫過用法的圖示，其餘用搜尋找。九千個不逐一成為知識條目（起草和總覽每次都會把整個類別讀一遍）。
- 作者的知識寫在少數圖示上（用法，跟模塊同一個做法）；寫過的優先給模型。

## 已決定（作者可否決）

- 預設線條風格，一張圖只用一種風格。
- 模型只寫詞；程式用整詞比對（`lan` 不會找到 `plane`）列出少數候選，再讓模型從候選裡挑或說都不合適。沒有模型或都不合適，就維持虛線框加建議字，不用規則硬湊。
- 圖示顏色跟著它所在的方塊或時間點；匯出用文件配色。
- 圖示庫裡已經沒有的 id：畫虛線框並給一行警告。
- Tabler 的公司商標（`brand-*`）不收。

## 試驗查到的事（2026-11-25，十二個圖示寫成 .pptx 與預覽）

- 8,996 個裡 8,993 個可以轉成路徑（剩下的用了 `use`）。
- Tabler 有 812 個圖示用「幾乎零長度的線段」畫點：線條要有圓頭才看得到，所以畫布的線條多一個 `cap`。
- Health Icons 有 2,483 個用 even-odd 填色；PowerPoint 的形狀沒有這個規則，洞會被填滿。轉換時把內圈反向繞。
- macOS 的 Quick Look 把自訂形狀畫得極小而且全部填滿：它不照 `a:path` 的 `w`/`h` 縮放，也不理 `a:noFill`。寫出時路徑空間改用形狀自己的大小、不填色的路徑標 `fill="none"`。真的 PowerPoint 沒試過。

## 第一階段：基礎（兩個套件，各自擁有檔案）

## 做到哪裡（2026-11-25 晚）

已完成並各自提交：

- `lore-icons`：兩套 8,996 個全部轉得成形狀；整詞搜尋。
- `lore-canvas`：線條圓頭、自訂形狀的路徑空間、不填色，寫進與讀回 .pptx。L-Slide 的測試全過。
- `lore-flow`：時間軸的點的 `icon` 是圖示 id 就畫圖示；流程圖多一種方塊 `icon`（`icon=<set:name>`）；預覽不再把多段直線連成一團。`examples/icons_sheet` 可以把幾個詞找到的圖示畫成一張 SVG 與一份 .pptx 來看。

看過的圖：43 個圖示一張、作者的四個時間軸模板換上圖示、兩張用圖示方塊的流程圖（門診到報告、WAN 到閱片室）。只在自己的預覽裡看過。

沒驗證：**真的 PowerPoint**。macOS Quick Look 裡 Health Icons 的洞被填滿、Tabler 的小點不見；判斷是 Quick Look 的限制，沒有把握。作者用 PowerPoint 開一次 `icons_sheet` 的 .pptx 才算數；若洞也被填滿，改成把洞切成獨立輪廓。

還沒做，依序：

1. 挑圖示的模型步驟：模型只寫詞 → `lore_icons::search` 列少數候選（加上作者寫過用法的）→ 模型從候選挑或說都不合適。另一個函式，應用程式自己決定要不要叫；不動現有起草的回覆順序。目前模型只從種類表知道有 `icon` 方塊，不知道有哪些名字，寫錯的 id 會畫成虛線方塊加一行警告。
2. L-Brain：流程圖那一組下面的類別「圖示」（兩個素材包＋寫過用法的）、搜尋路徑、在圖示上寫用法。
3. L-Slide：插入 → 圖示；它自己的編輯器要能畫圓頭線條。
4. 用文字（一段方法描述）起草一兩張流程圖給作者看；先做完第 1 步才有意義。
