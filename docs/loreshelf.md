# LoreShelf 設計草稿 — 2026-11-12

> 狀態：**草稿**。名稱已定（LoreShelf）；§10 的事項定了之後才做到那一段。

一個本機的檔案目錄：**不移動任何檔案**，用內容雜湊（sha256）認檔案，地端模型抽出時間與關鍵字標籤，
存成圖（節點＝檔案、邊＝相關），以 3D 球形介面瀏覽。找檔案不必記路徑，任何一條記憶（時間、主題、
相關的卡或簡報）都能走到。

## 1. 原則

- **不動檔案**：路徑只被記錄，不被管理；不寫 Finder 標籤（作者不用）。搬檔若做，一定有 undo log。
- **絕不上雲**：檔名、路徑、檔案內容不進任何 git remote、不進 KnowledgeBase 的 repo、不送雲端模型。
- **地端模型**：所有 `shelf-*` 任務 local only，地端失敗也不改用雲端，只說明原因。
- 檔案是真相、SQLite 可重建；測試只用暫存目錄與合成檔案。

## 2. 存放

| 內容 | 位置 | 說明 |
|---|---|---|
| 每個檔案一份紀錄（`files/<sha256>.json`）、標籤、邊、作者的修改紀錄、監看的資料夾 | `~/Library/Application Support/LoreForge/LoreShelf/` | 本機 git，只為了記錄標籤修改；**沒有 remote** |
| 防護 | 標記檔 `.lore-local-only`；`pre-push` hook 一律拒絕（repo 自己設 `core.hooksPath`，否則全域 hooksPath 會略過它）；`lore-gitsync` 拒絕有標記的 repo（`ErrorKind::LocalOnly`）；目錄在 iCloud Drive、`~/Library/CloudStorage`、LoreForge repo 裡或有 remote 就拒絕 | `LORESHELF_HOME` 可改位置 |
| 雜湊快取（`hash-cache.json`，以 size＋mtime＋inode 判斷）、SQLite／FTS、抽出的全文、縮圖、向量、球面座標 | `<cache>/LoreForge/shelf/` | 可刪 |
| 原檔 | 作者放的地方 | LoreShelf 永遠不是唯一副本 |

## 3. 資料模型

- **身分＝sha256**；`seen_at: [{path, first_seen, last_seen}]` 是觀察紀錄。同內容多處＝同一節點（重複偵測、只有一份＝備份風險）。0 位元組的檔案不算重複、也不算只有一份。
- 「下載時間」來自 quarantine，也包含從下載的壓縮檔解出來的檔案；有下載網址的只有直接下載的檔案。
- **時間是多條軸**，各標來源：檔案建立／修改、下載時間與網址（`kMDItemWhereFroms`、quarantine）、文件內的日期（PDF `CreationDate`、pptx `core.xml`、論文年份、git log）、首次被看到、最後打開（`kMDItemLastUsedDate`）。
- **邊**：`about`（主題／KB 卡）、`same-as`、`derived-from`（tex→pdf、匯出）、`cites`、`downloaded-from`、`opened-with`、`part-of`（專案內的子檔）。
- **macOS package**（`.app`、`.framework`、`.bundle`、`.photoslibrary`…）與**資料集**（> 500 個檔且 ≥ 90% 同副檔名的資料夾）也各算一筆，不逐檔記錄。
- **專案的身分**：git 專案用第一個 commit 的雜湊（同一個 repo 的兩份 clone 合成一筆）；非 git 專案用路徑 id 加指紋（標記類型＋頂層檔名），舊路徑消失、新路徑同指紋時合併，視為搬家。`build`、`target`、`node_modules` 只在專案內略過。
- **版控只記作者的修改**：掃描結果（`files/`、`reports/`）不進本機 git；作者的標籤修改另存（`edits/`），每次修改 commit 一次。
- **專案資料夾是一個單位**：有 `.git/`、`main.tex`＋`.bib`、`Cargo.toml`、`package.json`、`*.xcodeproj`、`pyproject.toml` 等標記的資料夾是一個節點（自己的／clone 來的看 remote）。標籤只從門面抽（README、`main.tex` 標題與摘要、git log 時間範圍）；`node_modules`、`target`、`build` 不讀；內部順序絕不動，搬檔只能整包。

## 4. 掃描與標籤

1. FSEvents 監看 → 雜湊＋檔案系統中繼資料（無模型）。
2. 內容抽取，沿用既有 crate：PDF `lore-docsrc`、pptx／docx `lore-ooxml`、LaTeX PaperComposer import；其他只記中繼資料。
3. 先對 KB 卡標題＋別名與 `tags.json`（LoreReader `nouns` 的 n-gram 比對），標籤優先落在既有知識上。
4. 地端模型補關鍵字與 2–3 句描述：`task.shelf-tag-file`（json_schema：`topics[] keywords[] doc_type summary confidence`），`shared_runtime` 的 `priority: "background"`，閒置才跑。
5. 收件匣：只請作者確認信心低的。
- **大檔案（原文書）**：只做檔案層級標籤與章節層級主題（目錄／書籤），不逐詞分析、不批次做卡。

## 5. 標籤向量與相似度

- **共現向量（預設，無模型）**：標籤共現統計（PPMI）→ 降維 32–64 維，反映作者自己的分類習慣。
- **語意向量（選用）**：閒置時以地端模型把標籤名稱轉成向量，補共現資料少的標籤。
- **檔案向量**＝標籤向量的 IDF 加權平均（連到的 KB 卡也當標籤）；時間另成一維（對數尺度）。
- 相似度＝標籤餘弦與時間核的加權；每個檔案的前 k（約 30）個鄰居在背景預算，存 cache。

## 6. 3D 介面

- 一般 app：點 Dock 打開；**不是全螢幕**（作者 2026-11-12：會擋住 Dock）——無邊框、半透明＋毛玻璃、圓角的一般視窗，預設為主螢幕可用範圍的 85%，可拖曳、可縮放，大小與位置記住；再點 Dock 或 Esc 收起；收起時釋放 WebGL。
- **外觀（2026-11-12 第三次定案：一顆真的球）**：整個畫面是一顆線框球（經緯線、邊緣一圈帶刻度的羅盤環、下方幾圈托著它的光環）。焦點在正對你的極點；鄰居在球面上圍著它，方向＝羅盤角度、離極點越遠越不相關；門檻外的鄰居是靠近球緣的小圓徽章（只有類型 icon）；更遠的真實檔案（上限 70）是球面其餘地方的柔和小點，多半在背面。**所有檔案節點都是小圓框**：發光的環、裡面是裁切的縮圖（沒有就放類型 icon）、下面一行小字檔名；焦點較大、用 `--accent`、外加一圈虛線。滑鼠停 150 ms 才放大成原比例的預覽卡，左下資訊卡跟著換。鍵是沿著球面的弧線，粗細＝相似度，接在圓框邊上，末端一顆小珠；候選的那條亮成 `--accent`。深度是真的：大小、霧、名稱是否顯示都由 z 決定，背面的東西轉動方向相反。配色全部取自主題 token（`--bg`／`--surface` 底，`--line-strong`＋`--accent-2` 球與環，`--muted`＋`--accent-2` 鍵與遠點，`--accent` 焦點與候選），淺色主題光暈改成陰影。圖層：地面（¼ 解析度，只畫一次）、球（½）、羅盤與鍵（全解析度），其餘是 DOM；1440×900@2x 合計約 26 MB。
- **球外面（2026-11-12）**：不留白——托著球的地面光環與放射線一路延伸到視窗邊緣、兩道傾斜的軌道、帶細刻度的外圈儀表弧、從遠處朝球收束的淡淡射線；都只畫在球的外側，不穿過球。
- **方向說明**：不是固定位置的字。因為同一個理由而相近的鄰居會排在一起，每一群在球緣外有一條引線和說明，講的是具體內容：「較早 · 2022 年 11 月」「名稱『車票』」「同類型 · PDF」「同來源 · 網域」，下面一行是數量與共同用途。拖曳時，東西過來的那一側的說明會亮起。目前由前端從鄰居的名稱、時間、類型、來源、用途算出；之後 server 在鄰居上給 `why`（地端模型讀出的標籤、知識卡的 edge 原因）時直接用它。
- **左下的資訊**：沒有框，一條細線加文字（名稱、一行說明、日期、位置、用途）；顯示滑鼠所指的檔案，否則是焦點。用途的「＋」可以選既有類別或直接打字新增（存成 `u:<名稱>`，左側篩選會跟著出現）。
- **開啟**：不放在資訊區。滑鼠停在節點上，預覽放大後游標變成手，點預覽＝開啟（資料集就地打開），預覽右下的資料夾鈕＝在 Finder 顯示。
- **視窗**：有左上角的紅黃綠鈕（紅＝真的關閉、結束 app；黃＝最小化；綠＝全螢幕），沒有標題列；可拖曳、可縮放。Esc 或再點 Dock 只是收起。
- **引導式搜尋**（上方列，`/`）：關鍵字不必在檔名裡——檔名、PDF 前幾頁內文、類別名稱、下載來源、所在資料夾、年份都算，每個詞都要對到。結果列出對到的地方（內文附前後文）；上面一排是「怎麼縮小」的選項（類別、年份、來源，附數量），點了就加進條件；什麼都還沒打時，這排就是進入點。Enter 或點一筆＝球轉到那個檔案。只在本機。
- **LoreEcho 同步開啟**：設定勾「開啟時同步開啟 LoreEcho」後，LoreShelf 開啟或從收起回來時，在背景叫出 LoreEcho（不搶前景），並把它的視窗放到 LoreShelf 視窗的右下角、縮到最窄（420 px）。此時球改放在「左側篩選」與「LoreEcho」之間的正中；沒勾時球在視窗正中。
- **LoreEcho 連動（第一版）**：LoreShelf 開著時，LoreEcho 每一輪會把你說的話拿去問 LoreShelf「這句話可能在講哪些檔案」（`/api/search?loose=1`：拉丁字詞＋中文相鄰兩字，依稀有度計分，檔名 > 類別 > 內文）。找到的檔案列在回覆下方「檔案：…」，球會直接轉到第一個，其他的點一下也會轉過去。檔名只在回覆由地端模型產生時才進提示；用 Claude 時只告訴它「找到 N 個、列在下方」。LoreShelf 這邊是 `POST /api/act {focus}`＋頁面長輪詢 `/api/events`。
- **拖曳＝轉球**：手指拖多少，極點上的東西就跟多少；放開後帶慣性；停下時最靠近極點的節點若已過半就成為焦點（球把它轉到正中，共有的節點沿球面滑到新位置），否則彈回。拖曳時球緣上「東西過來的那一側」亮一段 `--accent` 弧，旁邊是方向讀數。
- **像捲 PDF**：動的時候圖可以略糊但一定流暢（60 fps，不等載入），停下立刻清楚；拖曳中預先取下一個候選的鄰居與縮圖。
- **畫面上只有鄰域**（作者 2026-11-12 否決整台電腦的點雲：開資料夾不需要看到所有檔案的示意點）：焦點＋第 1 層（約 12 個）＋可關的第 2 層，沒有其他東西。焦點縮圖約畫面高度 1/3，第 1 層 96–128 px 附短檔名，第 2 層 48–64 px；類型一眼可辨。球形只留淡淡的深度感（徑向漸層），不畫網格。
- **拉遠＝時間分段**（本週、上週、本月、2026 春…，各顯示數量，點進去＝那段最新的檔案）；有標籤之後再改成主題區域。由內容推出的字（區域名、標籤）沒有好來源時寧可不顯示，不用檔名碎詞充數。
- **同一份文件的多個副本**（同 sha 已是一筆；另外依正規化檔名分組，如 `X.pdf`、`X (1).pdf`、`X.docx`）在畫面上疊成一張卡，標 ×N。
- 縮圖用 macOS QuickLook（`/api/thumb/{id}`，cache＋LRU），沒有縮圖時用類型圖示。第 2 層較淡、較小、略模糊，給深度感。
- **左側篩選**：兩組勾選，類型（PDF、簡報、圖片、專案、資料集…，由副檔名決定）與用途（論文、證件、作業、票券收據…，先用規則推斷，第 3 波改地端模型；作者手動修改優先，存 `edits/`）。同組 OR、跨組 AND；篩選套用到鄰居與時間分段，焦點不符時跳到最近的符合項。**證件**的縮圖預設模糊，滑過或點一下才顯示。
- **資料集**（如上千張 CXR）：圖上只是一個節點，縮圖是 2×2 拼貼並標張數；打開後是就地的資料集畫面（數量、大小、主要格式、子資料夾當篩選、標註檔清單、分頁且虛擬化的縮圖格），不把成員攤進圖裡。資料夾名稱出現在論文標題或前幾頁時，資料集與論文互連（因素「提及」）。
- **線只畫焦點往外 1–2 層**，滑到哪算到哪。方向讀數貼在焦點外側、手指滑的那一邊；羅盤字 ≥ 12 px。
- **360° 方向**：取焦點附近鄰居差向量的前兩個主成分 e₁、e₂（含時間），螢幕角度 θ ↔ `cos θ·e₁ + sin θ·e₂`，拆回標籤比例，例：`47° → 58% 影像分割 · 27% 綜述 · 15% 較新`。羅盤淡淡顯示 4–6 個角度，滑動時即時顯示手指角度的組合；滑過去＝在該角度選方向最吻合且最近的鄰居。換焦點時新基底對齊舊基底（不讓羅盤翻轉）。
- 鄰居小圖示依各自在 e₁、e₂ 上的座標排在焦點四周，所以螢幕角度＝羅盤角度；鏡頭內只有第 1、2 層鄰居，只有前 k 個連線，第 2 層從第 1 層往外長。
- 某個方向沒有鄰居時，補上較遠的鄰居（畫淡），每個方向都滑得過去；甩得再快也只跳一次；毛玻璃預設開。
- 操作分兩種模式：**拉遠**時拖曳是在主題區域之間移動；**近看**時滑動是往那個方向跳到最吻合的鄰居，滑動中標出放開會去的那個。捏合縮放切換兩種模式；點一下聚焦、點兩下用預設 app 打開（PDF → LoreReader）；Esc 收起。
- **左下資訊卡**：標題、2–3 句描述、標籤、時間軸、連到的 KB 卡數。**右下**留給 LoreEcho。
- 配色與字型：Lore 共用主題，由 `shelf-server` 送 `/theme.css`、`/theme.js`、`/api/theme`（和其他 app 同一套，跟著 `private/shared/ui.toml` 換）；縮圖與檔案圖示是文件，不套主題色。
- Icon：草稿 A（資料夾裡是節點與線），`LoreShelf/apps/desktop/icons/logo.svg`。
- **省資源**：不動就不畫（render on demand）；圖示合成一張貼圖集；縮圖按需從磁碟 cache 讀，貼圖記憶體上限＋LRU；計算都在 Rust。原生 WebGL 或 regl，不用整套 three.js。
- **沒在用時釋放資源**（依 `visibilitychange`、視窗 blur/focus，之後由 Tauri 傳入被蓋住／最小化）：① 使用中＝正常；② 失焦但看得到＝停止慣性與動畫，不再畫；③ 看不到超過 30 秒＝只留焦點縮圖，其他貼圖、線、鄰居快取都釋放，只留 id＋座標；④ 看不到超過 5 分鐘＝整個 WebGL 釋放，只留鏡頭與焦點狀態。回來時先畫焦點（目標 < 300 ms），鄰居再慢慢補。Tauri 透過 `LoreShelf.setActivity("active"|"blurred"|"hidden")` 告知狀態；系統自己收走 WebGL（context lost）也要能恢復；兩個延遲是常數（不放進齒輪）。後端掃描與模型標籤一律用背景優先權（macOS QoS background），有互動 app 用模型時讓路。
- 設定（齒輪）：鄰居層數、小圖示數、線的數量、縮圖解析度、貼圖記憶體上限、最高幀率（60/30）、毛玻璃開關、**開啟時同步開啟 LoreEcho**。

## 7. LoreEcho 串接

LoreShelf 不做聊天。LoreEcho 偵測到 LoreShelf 在執行時：
- 讀 `GET /api/view`（焦點、畫面上的鄰居、彼此的邊與共同標籤），可回答「這是什麼」「它跟旁邊那個的關係」、摘要。
- 回覆是 `{say, actions[]}`（json_schema）；actions 顯示成對話下方的建議話，點一下或說「好」就執行，經 `POST /api/act`。允許的動作只有：`focus`、`search`、`show_links`、`summarize`、`propose_cards`、`open`、`reveal_in_finder`；檔案 id 必須在目前畫面或搜尋結果裡。
- 帶到 LoreShelf 內容的那一輪**只用地端模型**。
- 視窗層級：LoreEcho 在 LoreShelf 的全螢幕視窗之上。

## 8. KnowledgeBase 串接

- **雙向連結只存在本機這一邊**：檔案紀錄存 KB 卡 id；KB 不存任何檔案資訊。KB 打開一張卡時向本機 LoreShelf 查「本機檔案 N」，LoreShelf 沒開就不顯示。
- 寫進 KB 只透過待審區（LoreEcho `propose_cards` → 預覽 → 作者確認）；寫入前檢查卡片內容不含目錄裡任何檔名或路徑片段，有就擋下；`source: "loreshelf"`，不寫哪個檔案。
- 做卡建議只在作者問時、針對眼前檔案或章節、3–5 個（KB 沒有、出現多、不在 ignore list）。每個候選：做成卡（進待審）／我知道了（my-vocab）／**N/A**。
- **新學習狀態 N/A**（作者定案；程式 id `na`，介面顯示「N/A」）：正式卡，「現在不想管，之後可能想」——沒有複習排程、不算到期、不會變 stale，隨時可改成 learning；LoreEcho 視為「知道有這個詞但還沒學」，不考。

## 9. 結構

- `commons/crates/lore-catalog`（新）：掃描、雜湊、讀 xattr、抽取器、時間軸、檔案紀錄、undo log、本機專用 repo 防護。
- `commons/crates/kb-core`：`State::Na`。
- `LoreShelf/`：`shelf-server`（axum）、Tauri 視窗、`web/`（共用 shell 與主題）。
- 其他 app 打開或匯出檔案時通知 LoreShelf（補 `opened-with`、`derived-from`）。

## 10. 分波與驗收

| 波 | 內容 | 驗收 |
|---|---|---|
| 1 | `lore-catalog` 只讀掃描：雜湊、中繼資料、時間軸、下載網址、重複、專案資料夾辨識；報告 | 樣本資料夾：重複數、各時間軸覆蓋率、只有一份的清單、專案辨識正確 |
