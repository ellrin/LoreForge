# L-Brain 知識中樞：設計書（第二版）

2026-11-24，未動工。作者的要求、討論的結論、分工。私人資料的實際數量在 `private/shared/docs/brain-hub-inventory.md`。

## 1. 目的

作者的 private know-how 散在各個 app，看不到全貌，有些存了卻沒有步驟在用。L-Brain 要成為**所有私人知識的資料庫與它的畫面**：看得到實體、分好類、有標籤、能排序、能新增修改移除（自己動手、從製作工具、或交給 AI），而且 Lore 之後多一個程式、或外面的應用程式要加入，都不用改 L-Brain。

這會動到整個 Lore：每個 app 的 private 知識都要在 L-Brain 看得到、改得了。

## 2. 作者定的規則

1. L-Brain 存的是**知識**，畫面上不出現檔案與路徑。知識卡只是其中一類。
2. 程式存的是模塊，但作者要看到**實體**：真的畫出來的樣子。點分類、再點子標籤，最後看到的是**很多張圖**（一格一張縮圖，下面一行名稱）。
3. 流程圖是一個大類，分三種大小：**元件**（conv layer、運算節點、LAN、WAN…）、**模塊**（encoder、decoder、attention…）、**流程圖**（一整張方法圖）。每一個都要有足夠的標籤（網路圖的元件標 web；論文來的流程圖標 machine learning…）。
4. 版型先**整理現有的**；新增的先預留區域。
5. 這是一個**資料庫**，L-Brain 是它的視覺化：能寫入寫出、有排序；AI 或其他工具能新增、移除、修改，**作者同意才生效**。
6. 要方便看、方便加：能接上製作的工具，能交給 L-Echo 微調。把一張流程圖的圖片交給 L-Echo，它拆成各階層的元件，作者同意後進資料庫。覺得投影片素材太少時，在 L-Brain 的頁面就能快速新增。
7. 清單**一列一個**，可以收合，點開往右展開。
8. 擴充：Lore 的程式可以自創類別，作者可以手動新增類別；Lore 以外的應用程式不能自創類別，只能**對齊**一個既有的 Lore 類別，或建立一組**獨立**的（選既有格式、自己取名、不和 Lore 串）。不替每個應用程式各寫 API。

## 4. 資料模型

### 4.1 格式、類別、來源（第一版的規則，不變）

- **格式**：一條知識的固定形狀，固定三件事：欄位、怎麼顯示、怎麼寫進 prompt。內建：知識卡、句型、常用詞、用詞對照、規則、範例、筆記、模板、圖形（本版把「圖的範本」細分，見 4.2）。之後加「單字」。
- **類別**：一組同格式的知識，有名字與主人（Lore 的某個程式，或作者手動）。
- **來源**：這一條是誰給的（作者、某個 Lore 程式、某個外部應用程式）。外部應用程式只會是來源。
- **學習狀態跟著格式走**（作者 2026-11-24）：「知識卡」這種格式的知識可以設定熟不熟，所以凡是知識卡格式的類別都有「複習」。知識卡和其他類別在左欄是同一層；它多一個可以開闔的鈕，展開是複習（以及待審、時間軸、圖譜）。之後新加的應用程式若用知識卡格式存知識，它那一組也要有同一個鈕。其他格式的知識不會被當成要學的名詞，也不進複習。
  - 現況：只有 L-Brain 自己的知識卡有學習狀態與複習；別的來源以知識卡格式存進來的一組，學習狀態與複習**還沒做**（要替那一組存每條的熟悉度）。

### 4.2 圖形類：實體、參考圖、三個階層

| | 內容 | 縮圖 |
|---|---|---|
| **實體** | 畫得出來的：程式畫法＋參數、存成圖形的模塊、一張完整流程圖的規格 | 用流程圖工具實際畫出來 |
| **參考圖** | 圖片＋結構描述；還畫不出來 | 圖片本身；放在**待製作**區 |

- 階層：**元件 → 模塊 → 流程圖**。每一條記著它**包含**哪些下一層的（一張流程圖用了哪些模塊，一個模塊由哪些元件組成），可以雙向點過去。
- 存成圖形的模塊放在流程圖工具本來就會讀的位置，所以一加進資料庫，L-Slide 與 L-Paper 的流程圖工具就能用，不需要新的讀取程式。
- 時間軸版型（作者 11-21、11-24 給的）：先以參考圖整理進「待製作」；流程圖工具會畫時間軸之後（docs/flow-figures.md §7）才變成實體。

### 4.3 標籤

三個各自獨立的面向，都可以再加：

| 面向 | 例子 | 來自 |
|---|---|---|
| 領域 | machine learning、medical imaging、web | 沿用知識卡的領域（唯讀借用，不另存一份） |
| 圖的種類／結構 | 架構圖、資料流、時間軸、網路圖、比較 | know-how 自己的 |
| 用途 | 論文、投影片、書 | know-how 自己的 |

另外每條可以有**觸發關鍵字**（內容出現這些字就適用），每個類別記著**用在哪些步驟**。

## 5. 資料庫

決定如下（作者可以否決）：

1. **用 SQLite，不用 Postgres**：單人、本機、不需要常駐的資料庫服務；知識卡的索引已經在用。
2. **每一次讀、排序、篩選、搜尋都經過資料庫**；所有寫入只走一個共用 crate（`lore-know`），不管是 L-Brain 的頁面、製作工具、L-Echo 還是匯入。
3. **存檔的本體仍是一條一條的文字紀錄**，資料庫由它們建立、每次寫入同步更新。原因：私人資料靠 git 同步，文字紀錄可以比對、合併、還原，二進位的資料庫檔不行；現有的 app 也照舊讀得到自己的資料，不必一次全改。對作者沒有差別：他面對的就是資料庫。
4. **寫出**：任何類別可以匯出成該格式的公開寫法（和外部匯入同一種），所以寫入寫出是同一個格式。
5. **刪除＝移到垃圾桶**，可以復原。
6. 知識卡維持現在的存法與功能（很多 app 直接讀它），只是在中樞裡成為一個類別。

## 6. 排序與篩選

每個清單都有：名稱、最近新增、最近修改、使用次數、最近使用、標籤數少的在前（找出標得不夠的）、未接上的在前；圖形類加上階層、實體／待製作。篩選：標籤（三個面向）、來源、類別。

## 7. 新增、修改、移除

三條路，寫入都走同一個地方：

| 路 | 怎麼做 | 適合 |
|---|---|---|
| **在 L-Brain 直接加** | 類別頁的「＋」：照格式填（文字類），或選一個既有的實體改參數另存（圖形類） | 快速補素材 |
| **製作工具** | L-Brain 裡直接打開流程圖編輯器（和 L-Slide 用的同一個），畫好「存成模塊／元件／流程圖」；L-Slide 編輯器裡選取的圖形也能「存進 L-Brain」 | 新的圖形實體 |
| **L-Echo** | 選一條知識請它改；或給它一張流程圖的圖片，它拆成流程圖、模塊、元件三層，對到資料庫已有的就連過去，沒有的提出新增 | 微調、從論文的圖擴充 |

AI 的規則：

- AI 只能提出**提案**（一批新增／修改／移除）。作者在 L-Brain 看到前後對照，同意才寫入；可以只同意其中幾條。
- L-Echo 拆圖要看圖，由 Claude 做（圖片會送到雲端；只用在論文的圖與作者自己的投影片）。
- 資料庫畫不出來的部分，以參考圖放進「待製作」，**不編造**一個實體。

編輯的範圍：文字與表格類（句型、規則、禁用字、筆記…）在 L-Brain 直接改；圖形在流程圖編輯器改；整包的東西（期刊模板、風格包）在 L-Brain 看、加標籤，內容在它的 app 裡改。

## 8. 畫面（Fable 負責，直接和作者討論）

先給作者看假資料的畫面，確認後才接真的資料。方向：

- **儀表板**（第一頁）：依 Lore 的程式分區，每個類別一格：名稱、數量、待製作／未接上的數量。另一區「獨立」放外部應用程式的各組。
- **類別頁**：左邊標籤樹（面向 → 標籤 → 子標籤）；中間**清單一列一個**，可依群組收合；點一列，**右邊展開**內容（預覽、標籤、觸發關鍵字、包含與被包含、用在哪些步驟、來源）。
- **圖形類的最後一層是縮圖牆**（作者的附圖）：一格一張實際畫出來的圖，下面一行「分類｜名稱」；待製作的另成一區。清單與縮圖牆可以切換。
- **知識卡清單**改成同一套：一列一個、群組可收合、點開往右展開（現在一列四個）。
- 排序與篩選在清單上方；「＋」在類別頁右上；AI 的提案在一個「待同意」的入口。
- 外觀：Lore 共用主題與外框，只放有指示作用的文字。

## 9. 外部應用程式（第一版的規則，不變）

「＋ 來源」→ 填應用程式名字 → **對齊**一個既有的 Lore 類別，或**獨立**（選格式、取名）→ 給照格式寫的資料（檔案或同一個通用入口）。同一來源再加一次＝整組取代它上次的；不符合格式的列出來；對齊的和 Lore 的一起用，獨立的只有看、搜尋、標籤，Lore 的步驟不讀。L-Brain 不替任何應用程式寫讀取程式。

## 10. Lore 再多一個程式時

新程式在自己的程式碼裡放一份宣告（它有哪些類別、各是什麼格式、用在它的哪些步驟），並經過 `lore-know` 讀寫。L-Brain 的儀表板自動多出它的區塊，不改 L-Brain。

每一步只做單元測試；做完一個小模組不跑端到端。整體的測試、每類走一遍、真的模型，全部完成後由 Fable 做一次。
