# L-Brain 成為知識中樞（規劃，2026-11-24，未動工）

作者 2026-11-24 的要求。這份只有規劃；盤點（數量、實際檔案）在作者的私人筆記 `private/shared/docs/brain-hub-inventory.md`。

## 1. 作者的話

- L-Brain 目前只存「知識卡」；大部分的 private know-how 都應該放在這裡，知識卡只是其中一個「功能類」。
- 要統一管理的：論文模板；論文寫作 guideline（要求、限制、限制用詞、範例、常用詞…）；投影片的論述法（要求、限制、範例…）；投影片流程圖的範本（架構圖、時間敘述圖…）；各種 Lore 需要管理的 private 知識。
- 知識也要**標籤化**，因為太多了，而且會一直增加。特定的結構會有的關鍵字，應該連到對應的 prompt，再做出對應的模組。
- L-Brain 打開是**儀表板**：各類知識的數量與細項。排版簡潔好用，和 Lore 整體風格一致。
- **外部非 Lore 的相容**：一個「＋」，別的應用程式的知識庫可以用特定格式或 API 加進來；名字可以是應用程式名稱；加入可以是整組重新建立。
- 這是大工程但重要；新功能不多，重點是重新規劃。先規劃。

## 2. 現況（2026-11-24 查）

- know-how 散在每個 app 自己的私人資料夾，各有各的格式：LaTeX 模板資料夾、CSV（一列一條規則或句型，有些已經有 `tags` 欄）、TOML、Markdown 筆記、JSON、.pptx 風格包、圖片＋描述。每個 app 的私人資料夾是各自的 git repo。
- 每個 app 用自己寫死的路徑去讀；沒有一個地方看得到「我有哪些 know-how、哪一步用了哪一條」。
- 有些存了但沒有任何程式讀（流程圖與時間軸的範例、寫作風格的參考分析）：存了、分析了、沒有接上。
- prompt 在程式裡（每個步驟是 lore-llm 的一個任務，各 app 的 `tasks.toml`，全部約 75 個）；私人資料是在執行時帶進 prompt 的。所以「連到 prompt」＝連到**任務**。
- 知識卡是 `nodes/<id>.json`。`lore_learn::load_names`、名詞掃描、複習、每日信、圖譜、L-Echo、L-Deck 都把 `nodes/` 裡的**每一個檔案**當成要學的名詞。know-how 若變成 node，模板或規則的標題會被當成論文裡的名詞、排進複習。
- L-Brain 已有的擴充點：`kinds.toml`（種類與欄位）、`apps.toml`（各 app 宣告自己的種類與連結）、`待審`（`POST /api/pending`，外部送來的卡先放這裡）。

## 3. 設計

### 3.1 一個目錄，內容留在原格式

- **項目（item）**：一件 know-how。依類別，一個項目是一個資料夾（一本期刊的模板、一個風格包、一張範例圖＋描述）、一個檔案（一份筆記、一個版型）或一列（一條規則、一個句型）。
- **類別（category）**：一種項目，宣告它的名稱、粒度（資料夾／檔案／列）、屬於哪個 app 的資料、怎麼讀（一個小的 adapter）、能不能在 L-Brain 裡直接編輯。知識卡是其中一類，也是唯一有**學習狀態**的一類。
- **內容不搬、不轉檔**：`.sty`、`.pptx`、CSV、圖片留在現在的位置與格式，app 照舊讀得到；識別名稱不改。L-Brain 持有的是**目錄**：每個項目的共同資料（下一節），放在 L-Brain 的資料夾裡（`hub/`），只記相對於該 app 私人資料夾的路徑，不記絕對路徑。
- know-how **不進 `nodes/`**，所以不會被當成名詞、不會進複習、圖譜預設不顯示。
- know-how 只屬於個人空間，從不進家庭空間。

### 3.2 每個項目的共同資料

| 欄位 | 內容 |
|---|---|
| 名稱、類別、來源 | 來源＝哪個 app（或外部應用程式的名字） |
| 標籤 | know-how 自己的一組標籤（用途：論文／投影片／圖；結構：時間軸、架構圖、比較…；段落：前言、方法…）。和知識卡的「領域」分開：領域只有 12 個顏色，而且會被整組覆寫 |
| 觸發關鍵字 | 內容裡出現這些字或這種結構時，這個項目適用（例：年份、歷史、演進 → 時間軸版型） |
| 用在哪些步驟 | lore-llm 的任務 id（可以多個） |
| 狀態 | 已接上（有步驟會讀到它）／未接上 |

已經有這些欄位的格式（CSV 的 `tags`、`section`）由 adapter 對過去，不存兩份。

### 3.3 讀取：共用 crate，L-Brain 沒開也能用

- 新的 commons crate（暫名 `lore-know`）：`目錄.項目(類別)`、`目錄.適用(任務, 內容文字) → 項目`。各 app 經過它拿 know-how，不再各自寫死路徑；L-Brain 的頁面與 API 是同一個 crate 上面的介面。L-Brain 沒開，app 照常工作。
- 一個步驟實際帶了哪些項目，記在那次工作的結果裡（看得到「這一頁用了哪個版型、哪幾條規則」）。
- 每接上一個類別都要有一個測試：暫存資料夾裡放一個項目、綁到任務，確認它真的出現在 prompt 裡。沒有這個測試不算接上。

### 3.4 儀表板

L-Brain 打開的第一頁。它的工作：**看到每一類有多少、點進去找得到、看得出哪些沒在用**。

- 每個類別一格：名稱、數量、底下的細項數量（例：寫作準則 → 規則／限制用詞／句型／範例）、未接上的數量。
- 點進類別：清單，用標籤篩選、搜尋；點進項目：內容預覽（文字、表格的一列、圖、模板的檔案列表）、它的標籤、觸發關鍵字、用在哪些步驟。
- 知識卡這一格進到現在的卡片清單、圖譜、複習，功能不變。
- 外觀用共用主題與共用外框，只放有指示作用的文字。

### 3.5 外部應用程式（「＋」）

- 「＋ 來源」：填應用程式的名字與它帶來的知識種類。來源登記在 L-Brain 的 app 登記表（現有的 `apps.toml` 擴充）。
- 兩種加法：(a) 一個資料夾或檔案，照公開的格式（JSON，一個項目一筆：名稱、種類、內文、標籤、連結）；(b) 本機 API。兩種都支援**整組重新建立**：同一個來源再匯入一次，就用新的那組取代舊的。
- 外部項目放在 L-Brain 資料夾裡自己的區域，預設**不接任何步驟**；作者綁了才會進 prompt。

## 4. 順序（每一步做完都可以停）

1. **目錄＋唯讀儀表板**：讀現有的檔案，不搬、不改任何 app 的行為。先看得到全部。
2. **第一個類別做到底**（建議：圖的範本，流程圖與時間軸）：項目格式、標籤、觸發關鍵字、綁到任務、進 prompt 的測試。這是「存了沒用」的實例，也接著 docs/flow-figures.md §7。
3. **在 L-Brain 裡加標籤、綁步驟、編輯文字類的項目**；寫作準則（規則、限制用詞、句型、範例）接上。
4. **其餘類別**一類一類接；每個 app 的讀取改走共用 crate，一次一個。
5. **外部來源「＋」**。
6. 之後：使用次數、最近用在哪。
