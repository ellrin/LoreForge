# L-Brain 知識中樞：規劃計劃書

2026-11-24，未動工。作者的要求與討論的結論。實際的數量與檔案盤點在作者的私人筆記 `private/shared/docs/brain-hub-inventory.md`。

## 1. 目的

L-Brain 現在只存知識卡。作者的 private know-how（論文模板、寫作準則、投影片論述法、圖的範本…）散在各個 app，看不到全貌，有些存了卻沒有任何步驟在用。

目標：**所有私人知識在 L-Brain 統一管理**。知識卡只是其中一類。知識要能加標籤、能一直增加；打開 L-Brain 先看到儀表板；別的應用程式也能把知識加進來，而且第 20 個應用程式加入時不用再寫任何程式。

## 2. 作者定的規則

1. L-Brain 存的是**知識**，不是檔案。畫面上只有一條一條的知識，不出現檔案與路徑。
2. 知識卡是其中一個功能類，不是全部。
3. 知識要**標籤化**。特定結構的關鍵字連到對應的 prompt，再做出對應的模組。
4. **Lore 底下的程式可以自創知識類別**；作者也可以手動新增類別（範例、文法、常用字、禁用字…）。
5. **Lore 以外的應用程式不能自創類別**，加入時只有兩條路：
   - **對齊**：選一個既有的 Lore 類別，照它的格式把知識加進去，和 Lore 的那一類串在一起用。
   - **獨立**：選一種既有的格式、自己取名字，建立一組獨立的知識；不和任何 Lore 程式共用。
6. 不替每個應用程式各寫一套 API。應用程式要服從固定的格式。
7. 外部知識由作者打開 L-Brain 按「＋」主動加入，不需要審核。

作者的兩個例子：

- 新應用程式選了論文的「文法句型」→ 它的句型進到那一類，寫論文時和原有的句型一起用。
- 新應用程式想加「單字」→ Lore 沒有這一類，所以獨立建立：選一種格式、取名字，不和 Lore 串。

## 3. 三個名詞

| 名詞 | 意思 | 誰決定 |
|---|---|---|
| **格式** | 一條知識的固定形狀：有哪些欄位、L-Brain 怎麼顯示它、它怎麼寫進 prompt | 程式內建，數量少，很少增加 |
| **類別** | 一組同一種格式的知識，有名字、屬於某個 Lore 程式（或作者手動建立） | Lore 的程式、作者 |
| **來源** | 一條知識是誰給的：作者自己、某個 Lore 程式、或某個外部應用程式 | 加入時記下 |

外部應用程式永遠只是**來源**，不是類別的主人。

## 4. 誰可以做什麼

| | Lore 的程式 | 作者手動 | 外部應用程式 |
|---|---|---|---|
| 新增類別 | 可以 | 可以（選一種格式、取名字） | **不行** |
| 把知識加進既有的 Lore 類別 | 可以 | 可以 | 可以（對齊；必須符合那一類的格式） |
| 建立獨立的一組 | — | 可以 | 可以（選一種格式、取名字） |
| 它的知識被 Lore 的步驟使用 | 是 | 類別接上步驟之後 | 對齊的：是。獨立的：**否** |
| 新增格式 | 要改程式 | 不行 | 不行 |

## 5. 格式

從作者現有的資料整理出來的（欄位以現有資料為準）：

| 格式 | 一條是什麼 | 主要欄位 | 現在的例子 |
|---|---|---|---|
| 知識卡 | 一個概念 | 標題、別名、摘要、說明、連結、來源；有學習狀態 | L-Brain 的卡 |
| 句型 | 一個可套用的句子骨架 | 段落、功能、位置、句型、例句、標籤 | 論文的文法句型 |
| 常用詞 | 一個搭配詞、片語或連接詞 | 種類、文字、用法、段落、例句、標籤 | 論文的常用詞 |
| 用詞對照 | 不用哪個字、改用哪個字 | 避免、改用、說明 | 論文的禁用字、共用的用詞規定 |
| 規則 | 一條要求或限制 | 類型、範圍、檢查方式、門檻、嚴重度、訊息 | 論文的寫作規則、期刊要求 |
| 範例 | 一段寫得好的文字 | 段落、功能、內文、出處 | 論文的範例段落、投影片備忘稿的範例 |
| 筆記 | 一份說明 | 標題、內文 | 寫作筆記、投影片的論述法 |
| 模板 | 一整套版面 | 名稱、適用對象、內容物 | 期刊的論文模板、投影片風格包、投影片版型 |
| 圖的範本 | 一張參考圖＋它的結構描述 | 圖、描述、結構（架構圖、時間軸…） | 流程圖與時間軸的範例 |

還沒有的格式：**單字**（字、讀音、意思、例句、語言）。作者的「文法」用「句型」格式就能放。新增一種格式是改程式的事，但加了以後所有類別與外部來源都能用。

每一種格式固定三件事，所以作者手動建立的類別與外部加入的知識都不需要新程式：

1. **欄位**（加入時照這個檢查）。
2. **顯示**（清單的一行、點開的樣子）。
3. **寫進 prompt 的樣子**（這一類被某個步驟使用時，每一條怎麼排進去）。

## 6. 類別

- 類別＝名稱＋一種格式＋主人（哪個 Lore 程式，或「手動」）＋用在哪些步驟。
- Lore 的程式宣告自己的類別（例：論文 › 句型、論文 › 禁用字、投影片 › 論述法、圖 › 時間軸版型）。
- 作者在 L-Brain 手動新增類別：取名字、選格式、放在哪個程式底下。剛建立時顯示**未接上**，等某個步驟設定要用它才算接上。
- 知識卡是唯一有**學習狀態**（記得／學習中、複習）的類別。其他類別的知識不會被當成要學的名詞，也不進複習。

## 7. 標籤與「關鍵字 → prompt → 模組」

- 每條知識有**標籤**（用途、結構、段落…），是 know-how 自己的一組，和知識卡的「領域」分開。作者可以新增標籤的種類。
- 每條知識可以有**觸發關鍵字**：內容出現這些字或這種結構時，這條知識適用。
- 每個類別記著**用在哪些步驟**（Lore 的步驟＝一個 prompt）。
- 執行時：某個步驟要它的類別裡、觸發關鍵字符合目前內容的知識 → 照格式寫進 prompt → 產生對應的東西。例：內容有年份、演進 → 帶上「時間軸版型」這一類裡符合的版型 → 畫成那個版型。
- 作者新增一條知識、設好關鍵字，不改程式就生效。每次實際用了哪幾條，記在那次的結果裡。

## 8. 外部應用程式

### 8.1 加入的過程（在 L-Brain 裡，作者主動）

1. 按「＋」。
2. 填**應用程式的名字**。
3. 選一條路：
   - **對齊**：選一個既有的 Lore 類別（例：論文 › 句型）。
   - **獨立**：選一種格式（知識卡、句型、常用詞…），替這一組取名字。
4. 給資料：一個照該格式寫的檔案，或讓應用程式送到 L-Brain 的同一個入口。
5. 結果：對齊的，出現在那個 Lore 類別裡，每一條標著來源；獨立的，儀表板多一格，以取的名字顯示。

### 8.2 只有一個入口

- 每種格式一份公開的檔案寫法（一條一筆，欄位就是 §5 的欄位）。
- 一個通用的入口：`來源名稱＋目標（某個類別，或某一組獨立的）＋一批知識`。檔案與本機 API 是同一件事的兩種送法。
- **L-Brain 不替任何應用程式寫讀取程式**。應用程式（或它的匯出）要自己產生固定格式。這是「第 20 個應用程式不用改程式」的代價，也是它成立的原因。

### 8.3 規則

- **整組重建**：同一個來源對同一個目標再加一次，用新的那批取代它上次的那批；只動這個來源的，從不動作者自己的或別的來源的。
- **不符合格式的**：列出來（哪一筆、缺什麼），不硬塞、不默默丟掉。
- **對齊的**：和那一類原有的知識一起被 Lore 的步驟使用；作者可以整個來源關掉或移除。
- **獨立的**：只有基本功能，儀表板的數量、清單、搜尋、標籤、預覽。Lore 的任何步驟都不會讀它。
- 獨立的一組以後想讓 Lore 用：先在 Lore 這邊有對應的類別（Lore 的程式新增，或作者手動新增），再把這個來源改成對齊它。外部應用程式自己不能做這件事。

### 8.4 例子

| 應用程式想加的 | Lore 有沒有對應的類別 | 走哪條路 | 結果 |
|---|---|---|---|
| 文法句型 | 有（論文 › 句型） | 對齊 | 進到論文的句型，寫論文時一起用，標著來源 |
| 單字（例如學語言的應用程式） | 沒有 | 獨立，格式「單字」（要先加這個格式）或「知識卡」，自己取名 | 儀表板多一格，可看、可搜尋、可加標籤；不和 Lore 串 |

## 9. 儀表板

L-Brain 打開的第一頁。它的工作：看到每一類有多少、點進去找得到、看得出哪些沒在用。

- 依 Lore 的程式分區，每個類別一格：名稱、數量、未接上的標記；對齊進來的外部來源在格子裡列出數量。
- 另一區「獨立」：外部應用程式的每一組各一格。
- 點進類別：清單（照格式顯示），用標籤與來源篩選、搜尋；點開一條：內容、標籤、觸發關鍵字、來源、用在哪些步驟。
- 知識卡那一格進到現在的卡片清單、圖譜、複習，功能不變。
- 外觀用 Lore 共用的主題與外框，只放有指示作用的文字。

## 10. 實作上的決定（作者不用管，記給之後的工作）

- 各 app 現有的知識留在原來的格式與位置，app 照舊讀得到；L-Brain 經過每個格式的讀取程式把它們呈現成一條一條的知識。外部加入的與作者在 L-Brain 手動加的，存在 L-Brain 自己的資料夾，帶著來源。
- 知識卡以外的知識**不放進知識卡的資料夾**：現在各 app 把那裡的每一個檔案都當成要學的名詞。
- 各 app 經過一個共用 crate 拿「某個類別的全部知識（自己的＋對齊進來的）」，L-Brain 沒開也能用。每個類別只有**一個合併點**（例：論文的句型在 L-Paper 載入寫作資料的地方合併），不是每個來源一個讀取程式。
- 每接上一個類別要有測試：暫存資料夾裡，一條外部對齊的知識確實出現在該步驟的 prompt 裡；一條獨立的確實沒有出現。
- 類別的宣告沿用 L-Brain 現有的登記表；宣告類別只有 Lore 的程式與作者手動可以做。
- 這些知識只屬於個人空間。

## 11. 順序（每一步做完都可以停）

1. **格式與類別的定義＋唯讀儀表板**：現有的知識全部看得到、數得出來；不改任何 app 的行為。
2. **第一個類別做到底：論文 › 句型**（作者的例子）：標籤、觸發關鍵字、接上寫作步驟、一個外部來源對齊進來並真的進到 prompt、整組重建、不符合格式的列表。
3. **「＋」的兩條路都能用**：對齊（已在第 2 步）與獨立（選格式、取名、基本功能）；加「單字」格式。
4. **作者手動新增類別**；在 L-Brain 裡加標籤、設關鍵字、編輯文字類的知識。
5. **其餘類別一類一類接**：圖的範本（流程圖、時間軸；接 docs/flow-figures.md §7）、禁用字與常用詞、規則、範例、投影片論述法、模板。
6. 之後：每條知識的使用次數、最近用在哪。
