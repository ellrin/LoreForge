# lore-notation — 對照表（notation registry）

Pure Rust, no network, no app knowledge. Shared by PaperComposer (PC) and
SlideComposer (SC); design: `../../../private/shared/docs/ecosystem-design.md` §5.

- `notation.json` data model, global profile file + per-document file, import/merge
- macro mode: `notation.tex` (`\newcommand` per entry), KaTeX macro map, insert text, Nomenclature
- LaTeX scanner: math segments, symbols, labels/refs, captions, floats, abbreviations, sentences
- consistency checks with jump locations (file, line, column, paragraph, sentence)
- auto-extract: a draft registry from an existing paper, plus an assistant hook (LLM via the app)
- UI: `commons/ui/notation-panel/` (`<notation-panel>` Web Component, demo)

```sh
cargo test -p lore-notation
cargo run -p lore-notation --example check -- crates/lore-notation/examples/sample \
    --notation crates/lore-notation/examples/sample/notation.json --out /tmp/report.json
```

## Files

| File | Where | Who writes it |
|---|---|---|
| `notation.json` | next to the document (`papers/<p>/notation.json`, a deck folder) | the app (atomic write) |
| `notation.json` (global) | `profile/notation.json` — the author's habitual symbols | the app |
| `notation.tex` | next to `main.tex`, `\input{notation}` in the preamble | `write_notation_tex` — only if absent or generated by us (first line `GENERATED_HEADER`); a user's own `notation.tex` is never overwritten, the new file gets a free name (`notation-2.tex`) |

The document file wins. Global entries reach the document only by an
explicit import (`Notation::import`); `Notation::merged` / `effective` give
the combined view for checks and the panel (`origin: "global"|"document"`).
"Same entry" = same id, same canonical LaTeX (symbols/operators) or same
`short` (abbreviations).

## Data model

```json
{ "version": 1, "entries": [
  { "id": "w", "kind": "symbol", "latex": "\\boldsymbol{w}", "macro": "vw",
    "meaning": "權重向量", "meaning_en": "weight vector", "gloss": "每個特徵的重要性",
    "shape": "d", "domain": "\\mathbb{R}^{d}", "unit": null,
    "defined_at": "sections/method.tex:10", "kb": "kb-…", "tags": [] } ] }
```

| kind | main fields |
|---|---|
| `symbol` | `latex`, `macro`, `meaning`, `meaning_en`, `gloss`, `shape`, `domain`, `unit`, `defined_at`, `kb` |
| `operator` | `latex` (`\operatorname{mean}` → `\DeclareMathOperator`), `macro`, `meaning` |
| `equation` | `latex` (body), `label`, `uses` (entry ids), `gloss` (spoken note for slides) |
| `figure` / `table` | `label`, `file`, `caption` |
| `abbrev` | `short`, `long`, `macro` |
| `term` | `meaning`, `meaning_en`, `kb` |

Two optional top-level lists (left out of the file when empty), read by the checker:

```json
{ "version": 1, "entries": [ … ],
  "conventional": ["AI", "ECGAN", "\\Delta"],
  "ignored": [ { "code": "label_unreferenced", "subject": "eq:loss" }, { "code": "caption_style" } ] }
```

- `conventional` — abbreviations, model names and symbol LaTeX that need no definition or
  expansion; usually in the global profile file (`profile/notation.json`). The panel's
  "標為慣用（不再提醒）" adds to the document file. `Notation::effective` combines both files' lists.
- `ignored` — findings the author dismissed ("忽略"): `code` + `subject` (no subject = every
  finding of that code). A grouped issue disappears when all its `subjects` are ignored.

`macro` is stored without the backslash (a leading `\` is accepted on load).
Tags: `conventional` / `well-known` (never needs a definition or expansion —
put `p` for p-values, `\mathbb{E}`, `AI` … in the global file), `auto`
(auto-extract), `undefined`, `needs-expansion`, `suggested` (from an assistant,
needs review). All fields except `id`/`kind` are optional and omitted when empty.

## API (main entry points)

```rust
// registry
Notation::load(path) / save(path) / from_json / to_json
Notation::import(&mut doc, &global, Option<&[&str]>, Conflict) -> ImportReport
Notation::merged(&global, &doc) -> Vec<MergedEntry>      // + origin
Notation::effective(&global, &doc) -> Notation
Notation::validate(&existing_macros) -> Vec<Problem>
Notation::is_conventional(name) / is_ignored(code, subject)
Notation::find_latex(latex) / get / get_mut / upsert / remove / free_id

// macro mode
macros::check_macro_name(name, &existing) -> Result<(), String>
notation_tex(&n, &existing) -> String                       // \newcommand / \DeclareMathOperator, \ensuremath where right
write_notation_tex(dir, &n, &existing) -> io::Result<PathBuf>
katex_macros(&n) -> BTreeMap<"\\name", body>               // for previews (PCTex.setMacros)
insert_text(&entry, InsertMode::{Macro,Literal}, in_math) -> String  // in math a trailing \name gets a space (`\speed ` + x ≠ `\speedx`)
insert_text_with(.., &RefWords) / notation_tex_with(.., &RefWords)  // a journal's reference words; the plain versions use RefWords::default()

// a journal's reference words ([ref_words] in a PaperComposer template)
RefWords { fig, tab, eq, sec: Option<String>, sentence_start: {kind → word}, mode: Option<"words"|"cleveref"> }
RefWords::default().snippet("fig", "fig:a", false) == "Fig.~\ref{fig:a}"   // also Table~\ref, Section~\ref, bare \eqref
rw.snippet(kind, key, sentence_start) -> String              // "Figure~\ref{…}", "Eq.~\eqref{…}", \cref / \Cref in cleveref mode
rw.word(kind, sentence_start) -> String                      // sentence_start word, else the kind's word, else the default
macros::nomenclature_tex(&n, "zh"|"en") -> String
macros::rename_macro(text, old, new) -> (String, n)          // rewrite uses when a macro is renamed
macros::replace_symbol(text, old_latex, new_latex) -> (String, replaced, skipped)  // literal mode

// scanning and checks
Document::load(dir_or_tex) / from_str / from_files            // follows \input/\include, skips our notation.tex
check_document(doc, &effective, &CheckOptions) -> Report     // registry macros are expanded while scanning
scan_document(doc, &n, &opt) -> Scan;  check::check(&scan, &n, &opt) -> Report
symbols::analyze(&scan, &opts) -> Symbols                    // occurrences + definitions per canonical key
math::canonical(latex) -> String                             // \bm{x}_i → \boldsymbol{x}

// auto-extract
extract_document(doc) -> Draft { notation, contexts }
extract::refine(&mut draft, &dyn NotationAssistant, "zh-TW") -> usize
```

`CheckOptions`: `caption_defines` (false — a caption that uses a symbol first
is reported), `grace_sentences` (3 — "…equation… where $x$ is …"),
`allow_abbrevs`, `section_labels`, `abstract_abbrevs`, `index_letters`
(`i j k l t d`), `max_locations`, `ref_words` (None — a journal's
`RefWords`: references are checked against its words instead of only for
mixed forms).

### Report

`Report { version, files, issues, summary: {code: n}, symbols: [...], abbreviations: [...] }`;
each `Issue { code, category, severity, message (繁中), subject, subjects, entry, locations, related, details }`;
`message` is "problem — how to fix it" (the panel shows the part after ` — ` as 建議);
`subjects` lists every subject of a grouped issue (one caption using several symbols too early);
each location `Loc { file, line, col, para, sentence, para_sentence, context, ord, snippet }`
(`para` counts blank-line paragraphs like pc-core, without the file's leading
`\section` line; `sentence` is the 1-based sentence in the file; `para_sentence`
the sentence in the paragraph, headings excluded; `context` is
`body|caption|table|heading|abstract|equation|definition`).

| code | category | severity | what |
|---|---|---|---|
| `undefined_symbol` | symbol | warning (info when it only appears in tables, e.g. a `$\Delta$AUC` header) | used, never defined in the text; display equations that use it are listed in `related` / `details` (no second `equation_undefined_variables` issue) |
| `used_before_definition` | symbol | warning | first use before the definition; display equations may be explained within `grace_sentences`. Everything one caption uses too early is **one** issue (`subjects`) |
| `symbol_multiple_meanings` | symbol / registry | warning | defined twice with different content (`n=|A|`, `n=|B|`); one letter in several fonts with meanings (`\boldsymbol{m}` vs `m`); a name subscript that is also a variable (`\lambda_m` vs `m`); registry: same LaTeX, different meanings |
| `meaning_multiple_symbols` | symbol / registry | warning | same description for different symbols |
| `unused_definition` | symbol | info | defined, never used again |
| `equation_undefined_variables` | equation | warning | display equation variables defined too late (never-defined ones are `undefined_symbol`) |
| `abbrev_never_expanded` | abbrev | warning (info for model / method names: mixed case `Grad-CAM`, digits, hyphen, or another acronym plus a prefix/suffix `ECGAN`) | used in the body, never "long form (ABC)"; well-known ones (`AI`, `allow_abbrevs`, `conventional`) are skipped |
| `abbrev_used_before_expansion` | abbrev | warning | body use before the expansion |
| `abbrev_expanded_twice` | abbrev | info | expanded more than once in the body |
| `abbrev_abstract` | abbrev | info | abstract uses it without expanding |
| `spelling_variants` | style | warning | `nonlinear` / `non-linear`, `Net-T` / `Net-Tiny`, with counts ("non-linear 11 次、nonlinear 1 次") and the less used spelling's places first |
| `label_unreferenced` | ref | warning (info for equations) | figure/table/equation label never `\ref`'d |
| `ref_undefined` / `label_duplicate` | ref | error | |
| `hardcoded_reference` | ref | warning | "Section III-C", "Fig. 2", "Table 1", "Eq. (3)" typed instead of `\ref` |
| `caption_style` | style | info | caption period / initial capital / Title Case / table caption above-below inconsistent |
| `ref_prefix_style` | style | info | `Fig.~\ref` and `Figure~\ref` mixed mid-sentence (only without `ref_words`) |
| `ref_word_style` | style | warning/info | with `ref_words`: a word naming the label's kind differs from the journal's (mid-sentence, or its `sentence_start` word); a word before `\cref`; in cleveref mode a word before plain `\ref` (info) or `\cref` at a sentence start (info). Plurals and other wording are not compared |
| `unused_entry` / `unregistered_symbol` / `registry_invalid` | registry | info/info/error | registry vs text; bad or clobbering macro names |

### How definitions are recognised (heuristics)

Structure (`$x=…$`, `$x\in\mathbb{R}^n$`, `$f:A\to B$`, left side of each row
of a display equation; numeric right sides are "values"), wording ("denotes",
"represents", "refers to", "is a/the", "let … be"), apposition ("the rib
segmenter $S$", "coefficients $a$, $b$, and $c$"), introduction ("generates
$x$", "… form"), inherited (`\theta` with `f_\theta`), derived
(`\tilde{p}^{\mathrm{f}}` from `\tilde p` and `p^{\mathrm{f}}`). Captions and
tables never define by default. `p<0.05` is the p-value convention. Known
limits: English prose only; macros with optional arguments are expanded
without them; `\def` with parameter text is ignored.

## Auto-extract and the assistant hook

`extract_document` builds a draft: symbols (meaning from the text, `domain` /
`shape` from `\in` definitions), custom operators, labelled equations (`uses`
filled), figures and tables (label, file, caption), abbreviations (long form or
`needs-expansion`). `Draft.contexts[id]` holds up to three sentences per entry.

`NotationAssistant` is a synchronous trait (`suggest(&AssistRequest) ->
Vec<Suggestion>`); the app implements it on top of `lore-llm` (one structured
task, model from the catalog), `MockAssistant` is for tests. `refine` only
fills empty fields and tags them `suggested`. This crate never calls a model.

## Integration

### PaperComposer (wave 2, B1)

Server (`pc-core` / `pc-server`), by path dependency `../commons/crates/lore-notation`:

| route | does |
|---|---|
| `GET /api/papers/:p/notation` | `Notation::merged(global, doc)` (entries with `origin`) |
| `PUT /api/papers/:p/notation` | save the document file; then `write_notation_tex(paper, …, doc_macros)` and `ensure_input("notation")` in `main.tex` preamble (only once, after `amsmath`) |
| `POST /api/papers/:p/notation/import` | `import(global, ids, conflict)` |
| `GET /api/papers/:p/notation/check` | `check_document(Document::load(paper), &effective, &opts)` → `Report` |
| `POST /api/papers/:p/notation/extract` | `extract_document` (+ `refine` with the lore-llm assistant when asked) → draft for review, never saved automatically |
| `POST /api/papers/:p/notation/rename-macro` | `rename_macro` over `sections/*.tex` (one sentence per line kept) |

UI (`ui/write.js`, `ui/tex.js`):

- toolbar "對照表" opens `<notation-panel>`; `notation-insert` → `put(inMath(ta) ? d.math : d.text)`
  (the existing `put`/`inMath` helpers of the symbol palette); set `panel.inMath = () => inMath(active())`.
- `notation-change` / `notation-add` / `notation-delete` → `PUT …/notation` (debounced); the server regenerates `notation.tex`.
- The panel validates macro names live with the rules of `check_macro_name` (set `panel.docMacros` to
  the document's own commands); "忽略" / "標為慣用" emit `notation-change` with `id: null` and
  `field: "ignored" | "conventional"` — save the document file as for any other change.
- `PCTex.setMacros({...paper_macros, ...NotationPanel.katexMacros(notation)})` so `\vw` previews.
- `notation-jump {file, line, para, para_sentence}` → open `sections/<file>`, paragraph `para`
  (same counting as `paper::parse_section`), sentence `para_sentence` (= line within the paragraph).
- The cross-ref picker keeps using `PCTex.labels`; figure/table/equation rows insert `Fig.~\ref{…}` / `\eqref{…}`.
- Hover: `new NotationTooltip(panel).attach(previewRoot)` and mark KaTeX nodes with `data-notation="<latex>"`.

### SlideComposer

- Each deck has its own `notation.json`, usually imported from the paper's (`import`) plus the global file.
- Equation boxes insert `latex` and optionally `gloss` as the bracket note (design §5 v0.2);
  native OMML via `lore-math` from the same LaTeX (macros expanded with `katex_macros`).
- `check_document` is for LaTeX sources; for slides the app runs `symbols::analyze` on a
  `Document::from_files` built from slide text boxes (one pseudo-file per slide, `file = "slide-07"`),
  so `notation-jump` names the slide.

### Events of `<notation-panel>`

`notation-insert {id, entry, mode, math, text, inMath}`, `notation-change {id, field, value, entry, notation}`,
`notation-add {entry, notation}`, `notation-delete {id, entry, notation}`, `notation-select {id, entry}`,
`notation-jump {file, line, col, para, sentence, para_sentence, context, snippet, issue}`,
`notation-loaded {what, url}`. See `commons/ui/notation-panel/notation-panel.js` header.
